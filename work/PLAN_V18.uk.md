# V18: розміри пакетів та вартість передавання для медіа

Повний обсяг і критерії завершення залишаються у `work/PLAN.md`.
Вихідний checkpoint: `156dea7`, worker v17 на N95/E90, 512-байтові пакети,
правильні Q15/CRC та чисте завершення. F05–F08 ще відкриті.

1. Встановити з native-коду, звідки беруться розміри STRM, в яких одиницях
   їх передає ARM, що перевіряють connection/transfer/allocation та які межі
   буферів. Поля DCD не змінювати без доведеного зв'язку з цими розмірами.
2. Додати до host/worker явні довжини пакетів з перевіркою меж. Заголовок
   займає 32 байти: WSOLA потребує 1760 байтів даних, тобто 1792 байти разом;
   MDEC input 1536 байтів потребує 1568 з заголовком. Розділяти корисні дані
   та повну довжину transfer. Старі досліди з офіційним RUN лишаються 512 Б.
3. Перевірити весь отриманий payload, Q15 на перших 240 значеннях, sequence,
   довжину, stop і остаточне очищення. Для вимірювання каналу використати
   режим без ARM CRC та без повторного Q15, з ARM FastCounter для кожного
   пакета. Не називати completion time чистою DMA latency або bandwidth.
4. До апарата: успішні ARM/DSP/SIS builds, перевірка DOFF/imports/ASM,
   збереження нових артефактів без перезаписування доказів v16/v17.
5. Fresh preparation з exact backups/readback. Спершу N95 512 Б один пакет;
   після clean FINAL0 — один пакет найближчого потрібного розміру, потім
   короткі серії більших пакетів та Q15. Відмова зупиняє апаратну серію до
   читання журналу й перевірки нового контракту.
6. Встановити host v18 на E90, звірити EXE і runtime profile та повторити
   підтверджені перевірки. Окремо записати умови й результати кожного телефона.
7. Після серій повернути original DSP/clock logs, перевірити SHA-256, PS/INFO.
   Опублікувати byte-exact журнали та перевірювані JSON з усіма статусами,
   розмірами, виміряними часами й межами висновків.
8. Оновити оцінку WSOLA/MDEC за виміряними розмірами. Окремими відкритими
   питаннями залишаються timer/idle, довга робота, audio coexistence й error
   lifecycle; не зараховувати їх короткими позитивними тестами. Узгодити
   документацію і зберегти checkpoint у приватному GitHub.
