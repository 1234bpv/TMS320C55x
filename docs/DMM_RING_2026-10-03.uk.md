## Що реалізовано і перевірено

Host41/candidate54, protocol38; DSP candidate52. Кільце **16384 B TOTAL**:
1024 B control, 15 input slots і 15 output slots по512 B; корисні дані
по480 B у slot, тобто7200 B на напрямок. Окремі два native notification
allocations по4096 B не входять у це кільце; по512 B notification у
кожному напрямку на exchange. Транспорт не є цілком безкопійним.

Ordinal30 виділяє кільце в native CMM region131072 B. Runtime перевірено
межі linear/physical region і всі чотири4KiB сторінки через BridgeUtil1.
Arg2 utility1 — **pointer to page-array pointer**, записи `{linear,physical}`
по8 B. CMM ring не належить двом окремим owner-scoped physical pools
із попереднього статичного аудиту. Native allocation утримується до
завершеного delete/free task, unmap, unreserve; page translation сама
по собі не доводить pinning чи всі атрибути chunk.

[Новий аудит backing](evidence/2026-10-03/native-ring-backing-audit.json)
перевіряє38 інструкцій і три kernel imports на кожному saved firmware:
ASIC selector2 physical/bytes → bridgecfg DPlatChunkHw::New(attrs1044)
→ config+260 chunk/+268 linear → board+172 reader[0] → context+24
→ CMM register. Factory cleanup отримує обидва retained chunk pointers.
За [первинним Symbian contract](https://raw.githubusercontent.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv/master/kernel/eka/include/memmodel/epoc/platform.h)
1044 означає user read/write, buffered uncached L1 і uncached L2.
Декодування спирається на public contract; runtime PTE dump і внутрішній
ASIC boot reservation тут не перевірені. Це global hardware mapping,
а не звичайні movable user heap pages; explicit pin/unpin API не заявлено.

Candidate61 використовує native ioctl2 для **cached own-channel state**,
і BridgeUtil1 для чотирьох сторінок власного буфера до/після exchanges.
Усі вісім records кожного run звірені; identities незмінні. Перед RUN
перевіряється retained own-node state1 та nonzero RMS MEM_valloc env.
Global queues не перераховуються; uniqueness спирається на native
allocator і незмінний live base. RomPatcher snapshots у цьому ring mode
відсутні. Clock probe окремо робив own-buffer patcher self-test, який
відмовив до PRCM access; це не total-session «no patcher» твердження.
Ordinal35/sub0 виявився control04000007, **не state getter**; його для
спостереження не викликали. [Аудити state](evidence/2026-10-03/native-processor-state-audit.json)
і [native owner](evidence/2026-10-03/native-ring-owner-audit.json).

Reserve/map використовують16384 **байтів**; mapped=`00300000` byte address,
DSP large pointer=`00180000` word address. Flags **17 (0x11)** перевірені
нативним PDD і правильними даними. Bit0=1 обирає translation через page list;
bit0=0 передає supplied address як physical. Початкові flags16 повернули
успішний map, але DSP читав нулі, result2/bad_words258. Ці проби мали чистий
teardown, FINAL−20, і не зараховані як correctness. Назву прапорця з іншого
TI userspace sample не можна переносити на цей firmware.

Власність передається **цілою областю16KiB**: ARM готує control/input,
utility2 clean→invalidate, notification handoff, ARM чекає без звернень до
кільця, output completion, utility2, перевірка даних. DSP читає input,
перевіряє всі слова, пише control/output і підтверджує completion.
Cache-line sharing не створює одночасних ARM dirty writes під час DSP
ownership. [Аудит compiled publication order](evidence/2026-10-03/dsp-ring-publish-audit.json)
підтвердив ring stores → completion-control stores → return → timing
→ notification fields → STRM_issue у точному archived DSP assembly.
[TI CPU guide,1.7.1](https://www.ti.com/lit/ug/spru371f/spru371f.pdf)
відрізняє W від завершення memory write у W+;
[TI Programmer’s Guide,4.4.3.1](https://edgeworker.ti.com/lit/pdf/spru376)
описує pending writes і bypass. Тому volatile/readback, instruction-cache
опис і absence of BCACHE exports не підміняють OMAP2420-specific external
write/notification visibility contract. Цей незалежний контракт ще відкритий.
[N95 ARM cache machine audit04.10](N95_ARM_CACHE_2026-10-04.md)
простежив utility2 ordinals378/376 до13 CP15 operations і3 DSB tails.
Це підтверджує конкретний ARM clean barrier; DSP→SDRAM/mailbox
acknowledgement ним не встановлено.

[Аудит native notification](evidence/2026-10-03/dsp-native-notification-audit.json)
від04.10 перевірив29 instruction sites на кожному saved firmware і
ініціалізовану таблицю DSM callbacks. STRM_create копіює14 C55 words
таблиці matched device, STRM_issue викликає callback на offset20 words.
У DSM таблиці це247DAC: channel type1 переходить у DMA, type2 — zero-copy,
інші — copy path. Native SHM_interrupt/SHM_interrupt2 читають mailbox
status за DSP-word address7F1041 і пишуть message за7F1022.
Це конкретний notification path; саме polling mailbox **не встановлює**
завершення попередніх SDRAM writes. Dynamic device/channel selection і
configured copy-function pointer історичних runs тут повторно не прочитані.

[TI DSP/BIOS5.31 GBL,2-118](https://software-dl.ti.com/targetcontent/legacy_files/targetcontent/bios/bios_5_31/sabios-h16/docs/packages/ti/bios/doc/spru404m.pdf)
описує posted/non-posted D-port writes через DCR.WPE для OMAP2420.
Read-only extraction первинного
[TI BIOS5.41 package](https://software-dl.ti.com/dsps/dsps_public_sw/sdo_sb/targetcontent/bios/dspbios/5_41_13_42/exports/bios_setuplinux_5_41_13_42.bin)
із `packages/ti/bios/include/gbl.h55` підтвердила I/O port200 і WPE mask80;
installer не запускався, SHA package/selected header збережені в audit.
Native BIOS обох телефонів —5.10: user-init лише BCLR ST3_MPNMC/RET,
GBL_DCRPOSTEDWRITE symbol відсутній. Це **не доказ WPE=0** і не підстава
приписувати documented default фактичному firmware. Наступна окрема
діагностика після свіжого clock gate має тільки прочитати port200 до/після
exchange; DCR writes і ретроспективне перенесення результату на61 не потрібні.

Після RUN: delete0 → free task0 → unmap0 → unreserve0 → free native ring0
→ free notifications0 → close/FINAL0. При невдалому delete/unmap хост
зберігає ресурси в QUARANTINE; автоматичного KILL немає.

## D2: межі висновку

`max(H+D,W)+S/N < A+W` еквівалентно одночасним `S/N<A` і
`W>H+D+S/N−A`. [Перерахунок](evidence/2026-10-03/ring-candidates-calculation.json)
використовує окремі N95 candidate54 та E90 candidate61 synthetic T/S
тільки як **явні сценарії**, із застереженням про непідтверджений DSP clock E90:
MDEC/SPU/WSOLA ще не виконувалися через це кільце, їх application T/W
не виміряні. SMLAD135–200us лишається оцінкою з попереднього аналізу.

MDEC: 1536 B input потребує4 slots/block; без repacking максимум3 blocks,
з hypothetical contiguous packing —4, не10 із старого припущення16KiB
на кожен напрямок. SPU PCM2934 B поміщається в7 slots; int32 payload7312 B
потребує16 slots і tiling. WSOLA1760 B payload потребує4 input slots;
асиметричний exchange і сам kernel тут не виміряні. Жоден кандидат поки
не має доведеного прикладного прискорення. Емулятор не редагувався.
