even without amortizing the setup. The emulator was not changed. The E90 was

## Computation boundary and numerical precision

The kernel between MDEC-KERNEL-BEGIN/END of the current local
PS1Emulator/pcsx_rearmed/libpcsxcore/mdec.c is recorded: source SHA256
AB19602EA3CF2DA4E05C4FDC7C4D689E801C3662E3833232B7028777187C2065.
The job starts **after RLE/dequantization, before IDCT**: 384 signed32
coefficients, 6 used-column masks and the black/white flag; it returns 192
packed uint32 RGB24 words. The current rl2blk already calls the IDCT; an
application integration would need a different boundary for this call.
RLE/DMA/IRQ/state are not part of the probe.

The ARM snapshot is kept exactly, including the ARMv6 usat and the modulo32
chroma. C55x int16 was replaced with long32 for the kernel arithmetic; three
rounding literals 1<<19 became 1UL<<19, and GNU noinline was replaced with TI
pragmas. RGB24 is written as 192 long words; C55x char16 is not used as a
serialized byte. Compile-time assertions check the widths. A copy of the GPL
notice/COPYING is kept. The ROM export __mpyli provides 32-bit multiplication;
the DOFF has 16 imports, all found in the saved N95 baseimage. The kernel
scratch belongs to the node context.

The independent Python integer oracle checks the absence of signed32 overflow
in the IDCT fixtures and exactly models the unsigned32 RGB wrapping. Eight
cases: zero/DC, first column, first row, dense coefficients, black/white,
saturation, coefficients over 16 bits. Non-DC coefficients are bounded to
±128; this is not an exhaustive legal game-input validation and not a
gameplay capture. ARM 3.4.3 and ARM 4.6.3 were also checked over all 384
post-IDCT values. The DSP was checked for each RGB24 word; all input words
must remain unchanged, and the headers and padding of both directions are
checked.

Ring 16 KiB TOTAL: 1024 control bytes + 15 input and 15 output slots of
512 B, 480 B payload each. Input per macroblock 1550 B, output 768 B; batches
1/2/4 use 4/7/13 input and 2/4/7 output slots. The explicit low/high 16
serialization preserves the signed32 coefficients. Wrap, index carry and
generation were checked during each series; the ARM does not touch the ring
during the whole-region DSP ownership.

## Two separate series of measurements

65/host50/protocol41: 3 short pilots of 8 jobs each and 3×3 full runs of 120
each. H included the full oracle audit, so this cohort gives correctness
evidence, not a final comparison with A. Its journals and timings are kept
separately.

66/host51 repeated the same number of runs with **exactly the same DSP65**.
H+D ends after the reconstruction of RGB24 into separate ARM memory; the
oracle/header/unchanged-input checks are performed after the time boundary. A
is 16 warm batches for each ARM compiler; the coefficient reset and oracle
checks are outside A, the kernel wrapper/loop/volatile sink inside. The ARM
kernels alternate before/after the DSP job. GCCE 4.6.3 uses the current core
flags -O2/-march=armv6/-mtune=arm1136j-s/-fno-exceptions/-fshort-wchar; the
isolated wrapper/cache/state differs from the live emulator. The EABI
attributes were removed and the flags stamped v4, as in the local core463 build.

**Each cohort separately:** 24 pilot jobs / 56 macros; 1080 full jobs / 2520
macros, 483840 RGB24 uint32 words and 3409920 ring uint16 words checked. Each
cohort has 6 full-series stock snapshots and 2 pilot snapshots. These are
brackets, not a continuous DVFS guarantee. There are no PRCM/performance
writes. Short CPU counters are not read; cpu_us=-1 means unmeasured. Raw DSP
ticks/counts_per_ms 164 are not converted into wall milliseconds.

The DCR I/O port 0x200 is read twice per job: all 2160 full-series readings of
each cohort are 0000, WPE bit 0x80 clear. Helper bytes A45102004804,
MOV port(#0200h),T0; RET; IO writes 0. This is the qualification of these runs
themselves, not an independent external-memory publication contract. The reads
may affect timing/ordering; this contract is still open.

## D2 and restoration

Instrumented S=setup+teardown for 66: p50 = 840178 µs, min 816344 µs. It
includes lifecycle journaling and is not the minimal production startup cost.
Useful ARM W=0. For the scenarios N16/64/256/1000, both strict conditions
S/N<A and W>H+D+S/N−A were checked. Blocking gain 0 in each scenario; even
N1000 gives the setup condition in only 2/1080 samples. Resident/asynchronous
alternatives with other S/H/D and an independent W were not measured; a general
impossibility of accelerating MDEC is not proven by this experiment.

After **each** cohort, all 5 N95 originals were returned, GET/SHA-equal: DSP,
stream journal, clock journal, EXE and hash. c55stream/ocprobe PS0; daemon
epoch 62209 boot 0 by n unchanged. This is the launch tuple, not a unique boot
ID. Source/out is now host51 and DSP65; the phone has the originals.
