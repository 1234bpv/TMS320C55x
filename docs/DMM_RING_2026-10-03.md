## What was implemented and verified

Host41/candidate54, protocol38; DSP candidate52. Ring **16384 B TOTAL**:
1024 B control, 15 input slots and 15 output slots of 512 B each; payload
480 B per slot, that is 7200 B per direction. Two separate native notification
allocations of 4096 B each are not part of this ring; 512 B notification in
each direction per exchange. Transport is not completely zero-copy.

Ordinal30 allocates the ring in native CMM region131072 B. Runtime verified
linear/physical region boundaries and all four 4KiB pages via BridgeUtil1.
Arg2 utility1 is **pointer to page-array pointer**, entries `{linear,physical}`
of 8 B. CMM ring does not belong to two separate owner-scoped physical pools
from the prior static audit. Native allocation is retained until
completed delete/free task, unmap, unreserve; page translation by itself
does not prove pinning or all chunk attributes.

[New backing audit](evidence/2026-10-03/native-ring-backing-audit.json)
verifies 38 instructions and three kernel imports on each saved firmware:
ASIC selector2 physical/bytes → bridgecfg DPlatChunkHw::New(attrs1044)
→ config+260 chunk/+268 linear → board+172 reader[0] → context+24
→ CMM register. Factory cleanup receives both retained chunk pointers.
According to [primary Symbian contract](https://raw.githubusercontent.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv/master/kernel/eka/include/memmodel/epoc/platform.h)
1044 means user read/write, buffered uncached L1 and uncached L2.
Decoding relies on public contract; runtime PTE dump and internal
ASIC boot reservation are not verified here. This is global hardware mapping,
not ordinary movable user heap pages; explicit pin/unpin API is not claimed.

Candidate61 uses native ioctl2 for **cached own-channel state**,
and BridgeUtil1 for four pages of its own buffer before/after exchanges.
All eight records of each run were verified; identities are unchanged. Before RUN
retained own-node state1 and nonzero RMS MEM_valloc env are verified.
Global queues are not enumerated; uniqueness relies on native
allocator and unchanged live base. RomPatcher snapshots in this ring mode
are absent. Clock probe separately did own-buffer patcher self-test, which
failed before PRCM access; this is not a total-session "no patcher" claim.
Ordinal35/sub0 turned out to be control04000007, **not state getter**; it was
not called for observation. [State audit](evidence/2026-10-03/native-processor-state-audit.json)
and [native owner](evidence/2026-10-03/native-ring-owner-audit.json).

Reserve/map use 16384 **bytes**; mapped=`00300000` byte address,
DSP large pointer=`00180000` word address. Flags **17 (0x11)** verified
by native PDD and correct data. Bit0=1 selects translation via page list;
bit0=0 passes supplied address as physical. Initial flags16 returned
successful map, but DSP read zeros, result2/bad_words258. These probes had clean
teardown, FINAL−20, and are not counted as correctness. Flag name from another
TI userspace sample cannot be transferred to this firmware.

Ownership is transferred **by the whole 16KiB region**: ARM prepares control/input,
utility2 clean→invalidate, notification handoff, ARM waits without accessing
the ring, output completion, utility2, data verification. DSP reads input,
verifies all words, writes control/output and confirms completion.
Cache-line sharing does not produce concurrent ARM dirty writes during DSP
ownership. [Compiled publication order audit](evidence/2026-10-03/dsp-ring-publish-audit.json)
confirmed ring stores → completion-control stores → return → timing
→ notification fields → STRM_issue in the exact archived DSP assembly.
[TI CPU guide, 1.7.1](https://www.ti.com/lit/ug/spru371f/spru371f.pdf)
distinguishes W from memory write completion in W+;
[TI Programmer's Guide, 4.4.3.1](https://edgeworker.ti.com/lit/pdf/spru376)
describes pending writes and bypass. Therefore volatile/readback, instruction-cache
description and absence of BCACHE exports do not substitute for OMAP2420-specific external
write/notification visibility contract. This independent contract is still open.
[N95 ARM cache machine audit 04.10](N95_ARM_CACHE_2026-10-04.md)
traced utility2 ordinals 378/376 to 13 CP15 operations and 3 DSB tails.
This confirms a concrete ARM clean barrier; DSP→SDRAM/mailbox
acknowledgement is not established by it.

[Native notification audit](evidence/2026-10-03/dsp-native-notification-audit.json)
from 04.10 verified 29 instruction sites on each saved firmware and
initialized DSM callback table. STRM_create copies 14 C55 words
of matched device table, STRM_issue calls callback at offset 20 words.
In DSM table this is 247DAC: channel type1 transitions to DMA, type2 — zero-copy,
others — copy path. Native SHM_interrupt/SHM_interrupt2 read mailbox
status at DSP-word address 7F1041 and write message at 7F1022.
This is a concrete notification path; mailbox polling itself **does not establish**
completion of prior SDRAM writes. Dynamic device/channel selection and
configured copy-function pointer of historical runs were not re-read here.

[TI DSP/BIOS 5.31 GBL, 2-118](https://software-dl.ti.com/targetcontent/legacy_files/targetcontent/bios/bios_5_31/sabios-h16/docs/packages/ti/bios/doc/spru404m.pdf)
describes posted/non-posted D-port writes via DCR.WPE for OMAP2420.
Read-only extraction of the primary
[TI BIOS 5.41 package](https://software-dl.ti.com/dsps/dsps_public_sw/sdo_sb/targetcontent/bios/dspbios/5_41_13_42/exports/bios_setuplinux_5_41_13_42.bin)
from `packages/ti/bios/include/gbl.h55` confirmed I/O port200 and WPE mask80;
installer was not run, package/selected header SHAs are preserved in the audit.
Native BIOS of both phones is 5.10: user-init only BCLR ST3_MPNMC/RET,
GBL_DCRPOSTEDWRITE symbol is absent. This is **not proof of WPE=0** and not a basis
to attribute documented default to actual firmware. Next separate
diagnostics after fresh clock gate only needs to read port200 before/after
exchange; DCR writes and retrospective carryover of the result to 61 are not needed.

After RUN: delete0 → free task0 → unmap0 → unreserve0 → free native ring0
→ free notifications0 → close/FINAL0. On failed delete/unmap the host
retains resources in QUARANTINE; there is no automatic KILL.

## D2: limits of conclusion

`max(H+D,W)+S/N < A+W` is equivalent to simultaneous `S/N<A` and
`W>H+D+S/N−A`. [Recalculation](evidence/2026-10-03/ring-candidates-calculation.json)
uses separate N95 candidate54 and E90 candidate61 synthetic T/S
only as **explicit scenarios**, with caveat regarding unconfirmed E90 DSP clock:
MDEC/SPU/WSOLA have not yet run via this ring, their application T/W
are not measured. SMLAD135–200us remains an estimate from prior analysis.

MDEC: 1536 B input requires 4 slots/block; without repacking maximum 3 blocks,
with hypothetical contiguous packing — 4, not 10 from the old assumption of 16KiB
per each direction. SPU PCM2934 B fits in 7 slots; int32 payload 7312 B
requires 16 slots and tiling. WSOLA1760 B payload requires 4 input slots;
asymmetric exchange and the kernel itself are not measured here. Not a single candidate yet
has proven application speedup. The emulator was not edited.
