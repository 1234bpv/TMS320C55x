# MDEC на N95: точність підтверджено, блокувальне перенесення не окупається

**Для виміряного six-IDCT + RGB24 job залишити ARM.** У виправленому
cohort66 жодне з1080 paired jobs не було швидшим через DSP навіть без
амортизації setup. Емулятор не змінювався. E90 не опитувався.

## Межа обчислення й числова точність

Зафіксовано kernel між MDEC-KERNEL-BEGIN/END поточного локального
PS1Emulator/pcsx_rearmed/libpcsxcore/mdec.c:
source SHA256 AB19602EA3CF2DA4E05C4FDC7C4D689E801C3662E3833232B7028777187C2065.
Job починається **після RLE/dequantization, перед IDCT**:384 signed32
coefficients,6 used-column masks і black/white flag; повертає192 packed
uint32 RGB24 words. Поточний rl2blk уже викликає IDCT; прикладна інтеграція
потребувала б іншої межі цього виклику. RLE/DMA/IRQ/state не входять у пробу.

ARM snapshot збережено точно, включно з ARMv6 usat й modulo32 chroma.
C55x int16 замінено long32 для арифметики ядра; три rounding literals
1<<19 стали1UL<<19, GNU noinline замінено TI pragmas. RGB24 пишеться як
192 long words; C55x char16 не використовується як serialized byte.
Compile-time assertions перевіряють ширини. Копія GPL notice/COPYING збережена.
ROM export __mpyli забезпечує32-bit multiplication; DOFF має16 imports,
усі знайдені у saved N95 baseimage. Kernel scratch належить node context.

Незалежний Python integer oracle перевіряє відсутність signed32 overflow
в IDCT fixtures та точно моделює unsigned32 RGB wrapping. Вісім cases:
zero/DC, first-column, first-row, dense coefficients, black/white,
saturation, коефіцієнти понад16 біт. Non-DC coefficients bounded ±128;
це не exhaustive legal game-input validation і не gameplay capture.
ARM3.4.3 і ARM4.6.3 перевірені також за всіма384 post-IDCT значеннями.
DSP перевірений за кожним RGB24 word; усі input words мають залишатися
незмінними, перевіряються headers і padding обох напрямків.

Ring16KiB TOTAL:1024 control bytes +15 input та15 output slots512B,
по480B payload. Input на макроблок1550B, output768B; batches1/2/4
використовують input4/7/13 й output2/4/7 slots. Явна low/high16
serialization зберігає signed32 coefficients. Wrap, index carry й
generation перевірені протягом кожної серії; ARM не торкається ring
під час whole-region DSP ownership.

## Дві окремі серії вимірів

65/host50/protocol41:3 short pilots по8 jobs та3×3 full runs по120.
H включав повний oracle audit, тому цей cohort дає correctness evidence,
а не остаточне порівняння з A. Його журнали й timings збережено окремо.

66/host51 повторив ту саму кількість runs із **точно тим самим DSP65**.
H+D закінчується після reconstruction RGB24 в окрему ARM memory;
oracle/header/unchanged-input checks виконуються після часової межі.
A —16 warm batches для кожного ARM compiler; coefficient reset та
oracle checks поза A, kernel wrapper/loop/volatile sink усередині.
ARM kernels чергуються до/після DSP job. GCCE4.6.3 використовує поточні
core flags -O2/-march=armv6/-mtune=arm1136j-s/-fno-exceptions/-fshort-wchar;
ізольований wrapper/cache/state відрізняється від живого емулятора.
EABI attributes вилучені й flags stamped v4 як у local core463 build.

**Кожен cohort окремо:**24 pilot jobs/56 macros;1080 full jobs/2520 macros,
483840 RGB24 uint32 words та3409920 ring uint16 words перевірено.
На кожен cohort6 full-series stock snapshots і2 pilot snapshots.
Це brackets, не continuous DVFS guarantee. PRCM/performance writes немає.
Short CPU counters не читаються, cpu_us=-1 означає unmeasured.
Raw DSP ticks/countspms164 не перетворюються в wall milliseconds.

DCR I/O port0x200 читається двічі/job: усі2160 full-series readings
кожного cohort0000, WPE bit0x80 clear. Helper bytes A45102004804,
MOV port(#0200h),T0; RET; IO writes0. Це кваліфікація саме цих runs,
не незалежний external-memory publication contract. Читання можуть
впливати на timing/ordering; цей контракт усе ще відкритий.

## D2 та відновлення

Instrumented S=setup+teardown для66: p50=840178µs, min816344µs.
Він включає lifecycle journaling і не є мінімальною production startup
cost. Useful ARM W=0. Для сценаріїв N16/64/256/1000 перевірені обидві
строгі умови S/N<A та W>H+D+S/N−A. Blocking gain0 в кожному сценарії;
навіть N1000 дає setup condition лише2/1080 samples. Resident/asynchronous
альтернативи з іншими S/H/D та незалежною W не виміряні; загальна
неможливість прискорення MDEC цим експериментом не доводиться.

Після **кожного** cohort повернуто всі5 originals N95, GET/SHA-equal:
DSP, stream journal, clock journal, EXE та hash. c55stream/ocprobe PS0;
daemon epoch62209 boot0 by n незмінний. Це launch tuple, не unique boot ID.
Source/out тепер host51 та DSP65; телефон має оригінали.
