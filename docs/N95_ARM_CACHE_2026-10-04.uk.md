# N95: точний ARM cache path для ring utility

У saved N95 firmware utility2 викликає ordinal378, потім376. Новий
[машинний аудит](evidence/2026-10-04/n95-arm-cache-path-audit.json) простежує
обидва entry points до cache routines. Він звіряє identity kernel/utility
з попереднім DMM audit,46 конкретних kernel sites,10 branch targets;
публікує436 bytes/109 instruction words вибраних ranges. Телефони та
deployed binaries не змінювалися.

| Шлях | Адреса | CP15 операція | Завершення вибраної routine |
|---|---|---|---|
| Ordinal378, clean MVA | 8006D66C | c7,c10,1 | DSB c7,c10,4 → return |
| Ordinal378, clean Set/Way | 8006D6A4 | c7,c10,2 | DSB c7,c10,4 → return |
| Ordinal376, invalidate MVA | 8006D638 | c7,c6,1 | return; у52-byte routine немає explicit DSB |
| Ordinal376, clean-invalidate Set/Way | 8006D6F8 | c7,c14,2 | DSB c7,c10,4 → return |

Імена CP15 operations зіставлено з первинним
[Arm ARM1136 TRM DDI0211I](https://documentation-service.arm.com/static/5e8e4306fd977155116aade2),
Table3-77,3-99/3-100 та CP15 c7 Flush operations,3-105..3-107.
Це reference для instruction semantics, не перевірка revision ядра N95
чи правил acknowledgement OMAP interconnect.

Обидва двоаргументні wrappers передають internal mask6: mask0x2 обирає
data-cache work, mask0x1 дорівнює нулю й пропускає instruction-cache work.
Конкретну range/whole-cache гілку визначає runtime cache metadata/threshold;
їх тут не зчитували. Перевірено обидві гілки, включно з loop backedges.
Наявність DSB у clean підтверджена точними інструкціями.

Після clean йде invalidate або clean-invalidate. Тому цілообласне
володіння важливе: якщо ARM створить dirty line під час DSP ownership,
цей helper може записати її поверх DSP result. У measured hosts ARM
не звертається до ring до notification completion і utility2. Short
invalidate має інший barrier tail; повний caller/context completion
contract цим вузьким аудитом не доведено.

DSB на ARM завершує попередні операції цього ядра згідно з його
архітектурним контрактом. Саме його існування не доводить, що запис
іншого master — DSP — завершився у SDRAM перед mailbox notification.
Отже DSP endpoint publication gate залишається відкритим. Старе посилання
SPRU376A4.4.3.1 на pending/bypass звірено з локальним primary text:
воно стосується CPU pipeline, а не встановлює OMAP fence.

Відтворення: `tools/rev/audit_n95_arm_cache.py` читає local saved ROM;
`tools/verify_n95_arm_cache.py` незалежно декодує13 CP15 operations,
перевіряє range hashes,10 branch destinations і3 DSB tails з published JSON.
За доступного ROM також перевіряє всі109 words у самому kernel.
Жоден скрипт не має phone I/O.
